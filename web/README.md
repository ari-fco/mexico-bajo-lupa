# web · México Bajo Lupa frontend

Static Next.js 16 app that consumes the JSON bridge generated by the
`etl/` pipeline. Deployed at [mexico-bajo-lupa.vercel.app](https://mexico-bajo-lupa.vercel.app).

For the project overview, sources, methodology and roadmap see the
[main README](../README.md). This file documents only the frontend
package.

## Stack

- **Next.js 16** (App Router, Turbopack) — fully static build, no
  application server
- **Tailwind v4** (CSS-first via `@theme`) with the Sequel tokens
  defined in [`../DESIGN.md`](../DESIGN.md)
- **MapLibre GL JS 5** for the choropleth on `/mapa` and the home
  preview
- **Recharts 3** for time series and Benford bars
- **DuckDB-WASM 1.33** wired in `lib/duckdb.ts` but unused while the
  JSON bridge fits the dataset size

## Project layout

```
src/
├── app/                 App Router pages (/, /mapa, /estado/[slug], …)
├── components/          UI: map, charts, tables, header/footer, ui primitives
├── data/                JSON build bridge produced by etl/export_json.py
│                        — imported synchronously by TS, hashed at build time
└── lib/                 queries, formatters, types, geo loader, duckdb wrapper

public/
├── data/                Parquet files for DuckDB-WASM (gitignored)
└── mx-topo.json         32-state TopoJSON (770 KB, served from CDN)
```

The `data/` directory under `src/` lives in the repository because the
JSON bridge is a build-time artifact: the app imports it
synchronously, so a clone with no Python toolchain can still build the
site. The Parquet files under `public/data/` are regenerated by the
ETL and stay out of the repo.

## Develop

```powershell
npm install
npm run dev
# → http://localhost:3000
```

The dev server uses Turbopack. Hot reload covers everything except the
JSON bridge — if you regenerate it from the ETL, restart `npm run dev`.

## Build

```powershell
npm run build
```

Produces a static export with prerendered pages for every route,
including the 32 state dossiers via `generateStaticParams`.
`/compara` is dynamic (uses `searchParams`) but everything else is
fully static and can ship to any CDN.

## Lint and types

```powershell
npx tsc --noEmit
npx eslint src/
```

Both should be clean. CI/Vercel build will fail on any lint error or
TypeScript error.

## Environment

The only env variable consumed is `NEXT_PUBLIC_SITE_URL`, used by
`app/sitemap.ts` and `app/layout.tsx` for absolute URLs. Defaults to
`http://localhost:3000` in dev and is set to the Vercel production
domain at deploy time.
